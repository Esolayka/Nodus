# Как сделать тему для Nodus

Если коротко: тему можно и подключить без пересборки (`Settings → Appearance → Load external theme…`, см. конец файла), и отредактировать/добавить прямо в исходниках. Тема — это набор CSS custom properties в `crates/desktop/src/theme/themes.css`, переключаемых атрибутом `data-theme` на `<html>`. Основная часть документа — про редактирование в исходниках; про загрузку файлом — последний раздел.

## Как это устроено сейчас

`ThemeProvider.tsx` хранит предпочтение (`"light" | "dark" | "system"`) в персистентном сторе настроек (`store/settingsStore.ts`), вычисляет реальную тему (`system` → `prefers-color-scheme`) и один раз ставит:

```ts
document.documentElement.dataset.theme = effectiveTheme; // "light" | "dark"
```

Всё остальное — чистый CSS. В `themes.css` бесстатный `:root` задаёт светлую тему по умолчанию, `:root[data-theme="dark"]` переопределяет то же самое для тёмной. Компоненты нигде не завязаны на конкретную тему — только на переменные (`var(--bg-primary)` и т.д.), поэтому переключение мгновенное, без перезагрузки и без прыжков раскладки.

## Полный список переменных

Общие для обеих тем (размеры, типографика, radius — тему не меняют, задаются один раз):

```css
--ribbon-width: 38px;      --sidebar-width: 270px;
--titlebar-h: 42px;        --tabbar-h: 40px;
--breadcrumb-h: 38px;      --statusbar-h: 24px;
--editor-width: 700px;

--font-ui: "Inter", -apple-system, "Segoe UI", Roboto, sans-serif;
--font-text: "Inter", -apple-system, "Segoe UI", Roboto, sans-serif;
--font-mono: "JetBrains Mono", ui-monospace, SFMono-Regular, Menlo, Consolas, monospace;
--fs-ui: 13px;  --fs-text: 16px;  --fs-small: 12px;

--radius-sm: 4px;  --radius-md: 6px;  --radius-lg: 10px;  --radius-xl: 12px;
--ease: cubic-bezier(0.2, 0, 0.2, 1);
```

Цветовые — то, что реально различается между `:root` и `:root[data-theme="dark"]`:

| Переменная | Что красит | Светлая | Тёмная |
|---|---|---|---|
| `--bg-primary` | фон редактора/основной поверхности | `#ffffff` | `#1e1e1e` |

| `--shadow-menu` / `--shadow-modal` | тени попапов/модалок | мягче | плотнее |

## Как отредактировать существующую тему

Просто меняешь значения в нужном блоке `themes.css` (светлая — верхний `:root`, тёмная — `:root[data-theme="dark"]`). Это чистый фронтенд: под `cargo tauri dev` окно подхватывает правку через Vite HMR прямо на лету, без пересборки Rust и без перезапуска процесса. Ничего регистрировать не нужно — компоненты уже читают эти переменные.

## Как добавить третью встроенную тему (например, "Sepia")

Пользовательского выбора темы из файла нет, но добавить ещё один вариант **в исходниках** — вопрос трёх мест:

1. **`themes.css`** — новый блок правил под своим селектором, например `:root[data-theme="sepia"] { --bg-primary: #f4ecd8; ... }` (скопировать список переменных из таблицы выше и переопределить).
2. **`store/settingsStore.ts`** — `ThemePreference` сейчас `"light" | "dark" | "system"`; добавить `"sepia"`.
3. **`theme/ThemeProvider.tsx`** — `resolveEffectiveTheme()` считает `system` через `prefers-color-scheme`, который умеет отличать только light/dark; новый вариант нужно обрабатывать как явный проход (`if (preference === "sepia") return "sepia"`), плюс `EffectiveTheme` расширить до `"light" | "dark" | "sepia"`.
4. **`components/Settings/SettingsModal.tsx`** — добавить пункт в список выбора темы (там же, где сейчас `light`/`dark`/`system`).

После этого `data-theme="sepia"` будет ставиться и читаться той же машинерией, что уже есть — никакого нового механизма городить не надо, это ровно тот же путь, которым добавлены текущие две темы.

## Загрузка темы из файла (Load external theme…)

`Settings → Appearance → Load external theme…`, рядом с «Создать тему». Открывает диалог выбора `.css`-файла, читает его тем же путём, что и плагины (`read_external_file_text`), и вытаскивает из текста все объявления `--custom-property: значение;` — неважно, в каком селекторе они лежат: файл специально не парсится как настоящий CSS, только как набор пар переменная/значение (`theme/customThemes.ts`, `parseCssCustomProperties`).

Из найденных переменных заполняются те же 10 полей, что и в таблице выше (`CUSTOM_THEME_COLOR_FIELDS` определяет соответствие, например `--bg-primary` → `background`); то, чего в файле нет, наследуется из текущей активной темы, так что частичный файл (скажем, только акцент и фон) — это нормально, а не ошибка. `base` (light/dark) не читается из файла отдельно — вычисляется по яркости `--bg-primary`. Название темы берётся из имени файла.

Результат — обычная запись в `settings.appearance.customThemes`, полностью персистентная и редактируемая дальше через тот же редактор темы, что и темы, созданные вручную (в отличие от внешних плагинов, чей код каждый раз приходится загружать заново — здесь достаточно один раз выбрать файл).

Если файл вообще не содержит ни одной из ожидаемых переменных, импорт не создаёт пустую тему — показывает ошибку прямо под кнопкой.
