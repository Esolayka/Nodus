# Архитектура

Живой документ: обновляется по мере прохождения этапов `02-ROADMAP.md`. Ниже — то, что уже решено на этапе 0.

## Хранилище

Vault — обычная папка на диске с `.md` файлами и вложениями в произвольной структуре подпапок. Служебные данные (индекс, настройки, кэш, история версий, установленные плагины) лежат в скрытой подпапке `.nodus/` внутри vault'а. Источник истины — файлы; всё в `.nodus/` — производные данные, которые можно пересобрать.

## Формат индекса

SQLite в `.nodus/index.sqlite` (`crates/core/src/index.rs`), через `rusqlite` (bundled, без системной зависимости). Таблицы:

- `notes(path PRIMARY KEY, title, mtime)`
- `links(from_path, to_path, target_text, kind)` — `to_path` может быть `NULL` (ссылка не резолвится, например заметка ещё не создана), `target_text` — сырой текст ссылки как в `[[...]]`, `kind`: `wikilink` / `embed`

Намеренно **не** хранится контекст/смещения ссылки — индекс используется только чтобы быстро найти кандидатов (`links.to_path = ?` либо совпадение по `target_text` для ещё не резолвящихся ссылок), а сам текст и контекст для панели обратных ссылок всегда перечитываются вживую с диска в момент запроса. Из-за этого протухшая строка в индексе может максимум привести к пропущенному кандидату, но никогда — к неверному сниппету на экране или к порче файла при перелинковке.

При старте — сверка `mtime` с диском (`Index::reconcile`), переиндексация только изменившихся/новых файлов, удаление записей об удалённых. Полная пересборка — просто повторный вызов `reconcile`; заново создаётся, если файл базы повреждён/отсутствует. Потеря `.nodus/index.sqlite` не может привести к потере заметок — максимум к переиндексации при следующем запуске.

Тегов (`tags`) и FTS5 пока нет — они появятся на этапе 3 вместе с полнотекстовым поиском.

## Граница между Rust-ядром и фронтендом

**Rust (`crates/core` + Tauri-команды в `crates/desktop/src-tauri`):**
файловые операции над vault'ом, парсинг и запись frontmatter (с сохранением незнакомых полей), парсинг `[[wikilinks]]`, файловый watcher, SQLite-индекс и полнотекстовый поиск, данные графа связей (узлы/рёбра — без раскладки), история версий, шифрование для синхронизации, изоляция и разрешения плагинов.

**Фронтенд (`crates/desktop/src`, React + TypeScript):**
весь UI и раскладка, редактор на CodeMirror 6 с live-preview, физика/раскладка графа (WebGL, отдельный поток), палитра команд и горячие клавиши, система тем, i18n, поверхность plugin API (вызовы уходят в Rust через Tauri-команды).

Правило: `crates/core` не знает о Tauri, GUI или сети — это единственная точка входа к vault'у, которой в будущем будут пользоваться и десктоп, и что угодно ещё (например MCP-инструменты или headless-режим), без дублирования логики.

**Осознанное исключение.** Резолвинг `[[wikilink]]` → путь заметки продублирован на фронтенде (`src/lib/noteIndex.ts`, зеркалит `resolve_target` из `index.rs`) — иначе подсветку ссылок и автодополнение в редакторе пришлось бы гонять через Tauri IPC на каждое нажатие клавиши. Источник истины по-прежнему Rust (команда `resolve_link_target` существует и protected тестами в `index.rs`); клиентская копия — только для рендер-цикла редактора, не более того.

## Структура репозитория

```
crates/
├── core/              # Rust: vault, frontmatter, wikilinks, watcher, SQLite-индекс — без GUI и сети
└── desktop/
    ├── src/            # React + TS фронтенд
    └── src-tauri/       # Rust: Tauri-команды, тонкие обёртки над crates/core
```

Дальше по роадмапу добавятся: `crates/sync-server` (этап 6), `packages/plugin-sdk` + движок плагинов (этап 5), `apps/mini-app` — Telegram Mini App (этап 7). Эти пакеты создаются на своих этапах, а не заранее.

## Темы

CSS custom properties на `:root`/`html[data-theme]`. Переключение — мгновенное, без перезагрузки. Тёмная тема — по умолчанию. Выбор темы (`light` / `dark` / `system`) на этапе 0 хранится в `localStorage` webview — это временное решение до появления persistent-настроек vault'а на следующих этапах, после чего выбор темы переедет в `.nodus/config`.

## Локализация

Все строки интерфейса — в `crates/desktop/src/i18n/locales/*.json`, никаких строк в коде компонентов. Стартовые языки — `ru` и `en`. Структура рассчитана на добавление языков через PR от сообщества, включая языки с письмом справа налево.
